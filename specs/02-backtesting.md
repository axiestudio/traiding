# Backtesting

Status: accepted for implementation.

## Goal

Run a historical, long-only backtest against Alpaca daily bars from the same
desktop app, without a second service, notebook or Python runtime. Results are
reported next to the trade ticket and stored locally.

## Strategy

**SMA crossover**, fully invested long or flat.

- Fast SMA and slow SMA over daily closes; defaults 20 / 50.
- Enter at the next day's open after the fast SMA crosses above the slow SMA.
- Exit at the next day's open after the fast SMA crosses below the slow SMA.
- No shorting, no leverage, one position at a time, fractional shares allowed.
- Fee in basis points is charged on both entry and exit notional; default 0
  (Alpaca is commission-free, but slippage can be modelled).
- Benchmark: buy and hold from the first close.

Executing on the next open avoids using a signal generated by the same close it
trades at.

## Request

`run_backtest`, camelCase wire shape:

```json
{
  "symbol": "AAPL",
  "days": 365,
  "fast": 20,
  "slow": 50,
  "initialCash": 10000,
  "feeBps": 0
}
```

Validation: symbol normalises like other commands; `days` 60–3650; `fast` 2–200;
`slow` 3–300; `fast < slow`; `initialCash` > 0; `feeBps` 0–100. Errors are short
sentences suitable for the ticket area.

## Response

{
  "symbol": "AAPL",
  "strategy": "SMA crossover",
  "fast": 20,
  "slow": 50,
  "days": 365,
  "start": "2025-11-19",
  "end": "2026-11-18",

  "finalEquity": 11234.56,
  "totalReturnPct": 12.3456,

  "maxDrawdownPct": -8.1234,
  "winRatePct": 62.5,
  "trades": 8,
  "wins": 5,
  "equityCurve": [
    { "time": 1732051200, "equity": 10000, "benchmark": 10000 }
  ],
  "closedTrades": [
    {
      "entryTime": 1732051200,
      "exitTime": 1733433600,
      "entryPrice": 181.2,

`openPosition` is the still-held entry when the test ends, or null. Times are
Unix seconds; dates are ISO calendar dates. All percentages are percentage
points, not fractions.

## Storage

New table in schema v2:

```sql
CREATE TABLE backtests (
    id          INTEGER PRIMARY KEY,
    created_at  TEXT NOT NULL,
    symbol      TEXT NOT NULL,
    strategy    TEXT NOT NULL,
    params_json TEXT NOT NULL,
    result_json TEXT NOT NULL
);
CREATE INDEX backtests_symbol_time ON backtests (symbol, created_at);
```

Every successful run is saved best-effort. A storage failure does not lose the
result shown in the UI. `StorageStats` gains `backtests`.

## UI

The right rail becomes two tabs: **Trade** and **Backtest**.

Backtest tab, top to bottom:

1. Symbol + range selector (1Y / 2Y / 5Y) + strategy label.
2. Fast SMA and slow SMA inputs, starting cash.
3. **Run backtest** primary button, disabled while running.
4. Result block: total return, benchmark, max drawdown, win rate, trades.
5. Equity curve vs benchmark, two line series in one chart.
6. Last closed trades, compact rows.

Copy: `Backtest`, `Trade`, `Range`, `Fast`, `Slow`, `Starting cash`,
`Run backtest`, `Return`, `Benchmark`, `Max drawdown`, `Win rate`, `Trades`,
`Equity`, `No runs yet`, `Running…`. Labels stay ≤ 2 words.

## Acceptance

1. A run on AAPL/1Y returns a curve whose length equals the fetched daily bars.
2. The first crossover enters on the following bar's open; no same-bar lookahead.
3. Max drawdown is ≤ 0 and total return matches finalEquity / initialCash.
4. The result renders a chart and a metric block at 1440×900 and 1080×720.
5. The table has one row after each successful run.
6. Unit tests cover crossover, no-trade, drawdown and validation.

## Non-goals

- Intraday backtests, shorting, portfolio-level multi-symbol allocation.
- Optimising parameters or walk-forward analysis.
